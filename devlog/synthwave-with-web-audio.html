Synthwave from code

28 October 2026 · Solothisgame234

Neon Drift has no sound files. The music and every effect are made live in the browser with the Web Audio API. That keeps the whole game at about 120 KB and lets the music react to how fast you're going.

The signal chain

Every sound goes through the same small mixer:

  • Music and effects each have their own volume (gain) node. Those are the two sliders in the pause menu.
  • Both feed a master gain used for mute.
  • The master goes through a compressor before the speakers, so a burst of effects (a smash, a combo, a new best) never clips or gets painfully loud.

Browsers only allow audio after the player interacts with the page, so the audio system starts on the first tap or key press.

Sound effects are tiny recipes

Each effect is one or two short notes with a pitch sweep, or a burst of filtered noise. A jump is a square wave sweeping from 300 Hz up to 640 Hz in about a tenth of a second. A dash adds a hiss of band-passed noise to a falling sawtooth. A crash combines low-passed noise with two falling tones. Orb pickups climb a pentatonic scale as your combo grows, so a long chain sounds like a melody and never hits a wrong note. A new best plays a quick rising arpeggio.

Every note has a short volume envelope: a fast rise and an exponential fall. That's the difference between a click and something that sounds like an instrument.

The soundtrack: four chords at 116 BPM

The music is a loop in A minor: A minor, F, C, G, one bar each, at 116 beats per minute in sixteenth notes. It has four instruments, all built from the same parts:

  • Kick: a sine wave dropping from 150 Hz to 42 Hz on every beat.
  • Hi-hat: a very short burst of high-passed noise on the off-beats.
  • Bass: a sawtooth jumping between two octaves of the chord's root, through a resonant low-pass filter that snaps shut after each note. That filter sweep is the classic synthwave "pluck".
  • Arpeggio: square-wave notes running through the chord.

Timing: the look-ahead scheduler

JavaScript timers are not precise enough for music. A setTimeout can fire tens of milliseconds late, and a busy frame makes it worse. Web Audio, on the other hand, can start a note at an exact time on its own clock. So the game uses the well-known look-ahead pattern: a timer wakes up every 25 ms and schedules every note due in the next 120 ms at its exact time.

function schedule() {
  if (nextT < ctx.currentTime - 0.2) nextT = ctx.currentTime + 0.05;  // tab slept: resync
  while (nextT < ctx.currentTime + 0.12) {
    playStep(step, nextT);          // kick, hat, bass, arp for this sixteenth
    nextT += SIXTEENTH; step++;
  }
}
setInterval(schedule, 25);

The first line handles a real problem. When a tab sits in the background, browsers slow its timers down. When the player comes back, a naive scheduler would try to "catch up" and fire seconds of notes at once. Instead, it notices it fell behind and starts fresh.

Music that follows the game

The game passes an intensity value from 0 to 1 to the audio system, based on how close you are to top speed. Two things change with it:

  • The bass filter opens wider (its cutoff goes from 320 Hz up to about 1,900 Hz), so the bass gets brighter and more aggressive as you speed up.
  • Above 30% intensity, the arpeggio joins in.

The music also gets quieter on the pause and game-over screens and comes back up when a run starts. The track never changes, but it feels like it builds with your run.

Why bother?

Audio files would have made the game several times bigger and slower to load on mobile data, and they couldn't react to gameplay. A hundred lines of synthesis code gives a soundtrack that loads instantly and follows the player.

Play Neon Drift with sound on to hear it.
