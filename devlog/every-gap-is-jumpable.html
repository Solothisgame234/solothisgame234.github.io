Making every gap jumpable

28 October 2026 · Solothisgame234

The worst feeling in an endless runner is dying to a gap that was never possible. Voltdart avoids that by building each gap from the same equations that move the ship.

The problem with random gaps

A simple endless runner picks a random gap width, say between 100 and 400 pixels, and hopes for the best. That breaks in two ways. Early on, when the ship is slow, a 400-pixel gap may be impossible. Later, when the ship is fast, a 100-pixel gap is boring. The fix is to stop thinking in pixels and think in time: how long can the ship stay in the air, and how far does it travel in that time at the speed it will have when it gets there?

The jump in numbers

Voltdart uses simple, constant gravity. The world is 720 units tall, and these are the actual values in the game:

SettingValue
Gravity2,900 units/s²
Jump speed (from the ground)980 units/s upward
Double jump speed860 units/s upward
Forward speed430 units/s, rising 0.004 units/s for every unit flown, up to 880

From those, everything else follows. Time to the top of a jump is v / g = 980 / 2900 ≈ 0.34 s. Jump height is v² / 2g ≈ 166 units. A full jump that lands at the same height is in the air for twice the rise time, about 0.68 s. At the starting speed of 430 units/s that covers about 291 units. At the top speed of 880 it covers about 595.

A double jump fired at the top of the first adds another 128 units of height. The ship peaks around 293 units up and stays in the air about 1.08 s, which covers 466 units at the start and over 950 at full speed.

Air time for any landing height

Platforms aren't all at the same height, so the generator needs air time for a landing that is dy units lower (positive) or higher (negative). Solving the motion equation for when the ship comes back down to that height gives:

function airTime(dy, dbl) {
  const g = GRAVITY;
  if (!dbl) return (JUMP_V + Math.sqrt(Math.max(0, JUMP_V * JUMP_V + 2 * g * dy))) / g;
  // double jump: rise to the first apex, then a second jump from there
  return T_APEX + (DJUMP_V + Math.sqrt(Math.max(0, DJUMP_V * DJUMP_V + 2 * g * (dy + H1)))) / g;
}

The Math.max(0, …) matters. If a platform is higher than the jump can reach, the square root would be of a negative number. Clamping it means the generator gets back the "reach the peak and stop" time instead of NaN, and is never told it can place an impossible ledge.

Speed is a function of distance

Because the ship speeds up with distance flown, not with time, the generator can work out exactly how fast the ship will be going at any point ahead:

const speedAt = x => Math.min(MAX_SPEED, BASE_SPEED + Math.max(0, x) * SPEED_RAMP);

So when it builds a gap starting at x, the maximum reach is speedAt(x) * airTime(dy, dbl). Real gaps are then picked as a fraction of that, usually 40% to 58% of the full reach. That leaves room for a jump that's a little early or late, and the gaps grow as the game speeds up, so it gets harder in a way that stays fair. Dashing is never needed to clear a gap. It's a bonus that gives you more room.

Orbs that teach the jump

The same equations place the orbs. For a gap, the generator samples the path of the ideal jump and drops an orb at evenly spaced moments along it:

function arcOrbs(x0, top, s, dbl, n, dy = 0) {
  const T = airTime(dy, dbl);
  for (let i = 1; i <= n; i++) {
    const t = T * i / (n + 1);
    addOrb(x0 + s * t, top - PLAYER_RADIUS + arcY(t, dbl));
  }
}

arcY(t) is the height of the ship t seconds into the jump. Players quickly learn that following an orb line is the right jump, and the game never has to explain it in words. You can see it in the screenshot on the home page: the orbs sit right where the ship will pass.

Short hops

Holding the jump button gives the full arc above. Letting go early makes gravity 2.4 times stronger while the ship is still rising, so it turns around sooner. The generator always assumes the full jump, so short hops are only ever an extra choice for the player, never a requirement.

What this buys

  • Levels stay fair at every speed, from the first meter to the top speed reached after about 2,800 m.
  • Difficulty comes from speed and timing, not luck.
  • Tuning stays in one place. Changing gravity or jump speed automatically changes how levels are built, so they can never fall out of sync.
